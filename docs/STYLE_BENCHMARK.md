# 本地画风比较：模型选择与验收口径

核查日期：2026-09-19。本文区分已经接入的实现、上游作者报告和待验证候选；不把论文结果当成用户的 NAI5 图片上的准确率。实现契约见 `CONTRACT.md` §16。

## 视觉模型排序

总实验室中的视觉 LLM 采用批内检索任务：图 1 是基准图，模型同时查看最多 7 张候选图，并返回画风最接近的前三名、0–100 批内解释分及理由。该分数用于说明同一模型在本轮为何这样排序，不是校准概率，也不能跨模型或跨批次比较。题材、角色、姿势、构图和背景内容在指令中明确排除；仍应使用“同风格不同内容”和“不同风格相同内容”的样本检查模型是否受内容干扰。

CLIP、CSD、MegaStyle 等本地编码器仍计算全部无序图对，使用人工组标签评估阈值、准确率、精确率和召回率。两类结果回答的问题不同，界面不会把视觉 LLM 的前三名自评分混进本地编码指标。

## 已接入的三个模型

| 模型 | 本应用用途 | 原生输入处理 | 本应用输出 |
| --- | --- | --- | --- |
| CLIP ViT-B/32 | 通用图像向量基线，检验内容相似是否干扰画风判断 | 短边双线性缩放、中心裁剪 224×224 | 512 维、L2 后余弦 |
| CSD ViT-L/14 | 专门训练的画风描述向量 | 短边 bicubic 缩放、中心裁剪 224×224 | style projection 的 768 维、L2 后余弦 |
| MegaStyle-Encoder | 面向画风相似度的 SigLIP 编码器 | 整图 bicubic 缩放 384×384 | attention pooling 的 1152 维、L2 后余弦 |

表中预处理描述本应用的现有 Rust 实现，沿用 `style/model.rs`、`style/csd.rs`、`style/megastyle.rs`，本次比较功能不更改旧索引算法。传入的是本地原文件，不是 UI 缩略图；“读原图”仍会执行模型要求的缩放/裁剪，不等于每个模型都保留边缘信息。

CLIP 的官方实现同时提供图像与文本编码器，训练目标为图文匹配。这里仅复用图像塔，作为通用基线；相似的人物、服装、场景也可能拉高分数。这是选择基线的依据，并非对某张图片的判断。[CLIP 官方仓库](https://github.com/openai/CLIP)

CSD 作者明确以图像画风描述与检索为目标。上游仓库目前仍说明发布权重与论文数字有差异，因此不能给用户承诺论文里的准确率。仓库代码标 MIT，作者链接的权重卡标 CC-BY-4.0；代码与权重许可应分别保留。[作者仓库](https://github.com/learn2phoenix/CSD)、[作者权重卡](https://huggingface.co/tomg-group-umd/CSD-ViT-L)

MegaStyle 官方提供独立的 Encoder 画风评分路径，以及另一个用于风格迁移的 FLUX 路径。本应用只使用 Encoder。官方 2026-09-02 更新了 MegaStyle++ 的论文与数据集公告；这不代表本应用已切换新权重，更不代表应该自动替换现有模型。[MegaStyle 官方仓库](https://github.com/Tencent/MegaStyle)

## 待验证的其他候选

下表只是研究记录。它们没有接入下载器或比较命令，界面不能把它们展示成可运行选项。

| 候选 | 一手资料确认的机制 | 对本项目的判断与下一步 |
| --- | --- | --- |
| IntroStyle | 利用扩散模型中间特征的通道均值/方差，以 2-Wasserstein 距离比较画风；无需为画风重新训练 | 方法与现有余弦编码器不同，值得独立实验。不能将其距离直接塞入 `cosine` 字段；先固定扩散模型、层、时间步与随机性，测 Mac 运行成本。 |
| Anime Images Style Embedder v4 | 作者用 DINOv3 的 CLS 特征加 MLP 生成动漫画风向量，模型卡注明需要获取 DINOv3 权限 | 与动漫插画目标接近，优先做小规模配对测试；先核查完整权重、许可与离线推理，不能因输出维度小就断言更准确。 |
| Anima Style Embedding v2 | 作者报告面向动漫/插画、1–8 张参考、1024 维向量；组合 VAE、DINOv3 与 Anima 描述符 | 可能适合多参考研究，但依赖链较长，模型卡有非商业许可；应先验证外部特征是否齐全，再考虑本地接入。 |
| anime-style-classifier-v5 | EfficientNet-B2，四类动画制作风格，提供 1408 维倒数第二层特征 | 适合作为粗粒度风格对照；四类分类结果不能证明能分辨细小的 NAI5 画师配方差异。 |

WD Tagger 等动漫标签模型应作为内容识别对照；其官方输出包含分级、角色和通用标签，不能把标签分类准确率直接解释为画风相似度准确率。[WD EVA02-Large 官方模型卡](https://huggingface.co/SmilingWolf/wd-eva02-large-tagger-v3)

## 先建立真正要回答的问题

本实验回答“这两张图在人工定义的画风上是否接近”。它不能证明两张图使用了相同的 NovelAI 画师串，也不能识别真实作者身份。同一画师可能有多个风格；不同配方可能产生近似外观。若按生成配方分组，应将标签明确记为“同配方”，不要称为“同画风真值”。

建议在用户 Mac 本地准备至少四种配对，素材不上传仓库：

1. **同风格、不同内容**：换角色、动作、场景，检查内容变化是否造成漏判。
2. **不同风格、相同内容**：固定角色和构图，换线条、上色与材质，检查内容是否造成误判。
3. **容易判断的正例和负例**：用于检查路径、顺序和分数方向。
4. **含糊的边界例**：保留“未标注”，不要硬塞入阴性；单独人工看。

两张重复文件或仅做轻微 JPEG 压缩的版本适合数值健全性检查，不应大量充当画风正例。否则高分可能只证明识别了同一幅画。角色、裁剪范围、清晰度、画面中背景的占比都应记录，以便解释模型分歧。

## 阈值、指标与数据划分

- 默认阈值 `0.8` 仅是界面起点，尚未校准；`cosine >= threshold` 才作为本次实验的阳性预测。`0.8` 不等于“80% 同画风概率”。每个模型单独设置，不把不同模型的原始分数直接排名。
- 人工组标签都非空时，同组为正例、异组为负例；任一端未标注则不参与准确率。组标签隐含组内风格一致的假设，无法表达的含糊图应留空。
- 每一对只计一次，不计自配对。记录 TP、FP、TN、FN 与有效配对数；accuracy = `(TP+TN)/N`，precision = `TP/(TP+FP)`，recall = `TP/(TP+FN)`。分母为零显示未知，不显示 0% 或 100%。
- 缺权重、坏图、推理失败不能作为阴性或零分参加统计。本版界面按各模型的有效判断分别计算指标，并显示覆盖量；没有自动选出赢家。人工比较模型时应只取共同成功的配对，避免失败多的模型因只剩简单题显得更好。
- 一批 N 张图最多得到 `N*(N-1)/2` 个配对，但这些配对共享图片，不能当作同样数量的独立样本。调阈值与最后报告效果应使用不同图片/风格组；不要随机拆开同一张图片参与的配对到训练与验证两边。
- 已从当前这批数据调过阈值时，将显示值称为“当前样本结果”。在保留的一批新图上复验后，才能讨论泛化表现。样本过少时展示混淆矩阵和错例比给一个漂亮总分更有用。

以上为本项目的实验设计，不是引用模型卡中的性能承诺。用户已经偏好 MegaStyle，可以先把它当主要候选，再用同一批图与 CSD、CLIP 做盲评；保留模型不一致的具体图片对供人工复看。

## 本地运行与复现

`style_compare` 接收 2–32 张本地图片及 1–3 个固定模型 ID。路径必须绝对且规范化后互不相同；同一文件的符号链接也算重复。每张最多 32 MiB，合计 128 MiB；每张最多 33,554,432 像素，长边 16,384，长宽比最多 64:1，解码器另有 256 MiB 内存预算。超限明确报错，不静默缩图。整个请求先冻结图片字节、尺寸和 SHA256，然后所有模型复用该快照。

推理沿用设置中的 Auto / Metal / CPU 偏好，结果记录实际设备和回退原因。模型逐个加载，批次受注册 batch_size 与像素预算共同约束；不读取/写入向量索引，不更改当前画风模型，不接触筛选决策。缺权重独立报错，需用户从已有设置页下载。

`load_ms` 包含取得/加载模型的时间，缓存命中会很短；`encode_ms` 包含冻结图片的重新解码、编码与配对计算；`total_ms` 是该模型本次处理时间。顶层 `elapsed_ms` 还包括输入冻结与等待共享推理锁的时间。比较性能时分别记录冷启动和热缓存，不把下载时间混入编码速度。

`style_compare_cancel()` 幂等请求停止；取消期间仍占用本次比较槽，直到当前阻塞推理结束。不会尝试强杀 Candle 工作线程。新比较并发调用返回 `batch_running`。取消不改模型下载任务，也不撤销其他实验室的任务。

离线测试（不下载真实权重、不调用任何模型 API）：

```sh
cd src-tauri
cargo test --offline --locked --lib style::compare::tests -- --test-threads=1
cargo test --offline --locked --lib commands::style_compare::tests -- --test-threads=1
```

测试使用合成 PNG、假向量和小型随机 CLIP，覆盖输入/路径边界、字节冻结、所有无序配对、非法向量、取消、缺权重及混合成功/失败。它们验证管线正确性，不证明真实模型的画风准确率。Linux CI 的 CPU 测试也不能代替用户 Mac 上的 Metal 实测。
