# Mac 内置更新

从 v0.5.9 起，点击左下角版本号，或打开 **设置 → 软件更新**。

1. 首次选择 Mac 上已有的 `nai5-codex-lab-public` 源码文件夹（包含 `.git` 和 `package.json`）。
2. 点 **检查更新**，读取 GitHub 仓库 `hujiehuan/nai5-codex-lab-public` 的正式版本标签。
3. 有新版时点 **准备更新**。软件使用本机现有 Git 认证、Node/npm、Rust/Cargo、Xcode 工具链，在独立目录构建新版 `.app`。界面显示真实阶段和日志；离开设置页后仍继续，可取消。
4. 准备完成后点 **安装并重启**。待当前本地任务和保存请求结束，软件先保存实验工作区并备份筛选数据库，再退出、替换应用并重新打开。

首次安装带更新入口的版本仍需手动构建一次。之后不必每次手动运行 Git/npm/Cargo 命令，但源码目录和构建工具仍需保留。这是本机源码更新，不是下载预构建安装包；编译可能持续数分钟或更久。

## 首次安装 v0.5.9

先退出旧软件，备份 `~/Library/Application Support/moe.vivian.codexlab/`；不可删除这里的 `library.db`。也可以按 [本机只读校验](LOCAL_DATABASE_CHECK.md) 在升级前后记录决策摘要。

在 Mac 的**源码文件夹**打开终端，逐行运行：

```sh
git pull --ff-only origin main
npm ci
npm run tauri build
open src-tauri/target/release/bundle/macos
```

把生成的 `NAI5 Codex Lab.app` 替换“应用程序”里的旧版，然后打开。不要在 `moe.vivian.codexlab` 数据文件夹里运行这些命令，也不要从 DMG 内直接运行软件进行内置安装。

## 保留什么

- 原源码工作树及未提交修改不被切换或清理，更新构建使用独立 worktree。
- 数据目录、筛选决策、图片和实验记录仍留在本机；更新不会上传数据库或法典数据。
- 升级前的一致性数据库副本保存在数据目录的 `backups/`；旧应用本体也会保留供恢复。
- 钥匙串服务名与进程读缓存不变。未签名的新本机构建仍可能需要 macOS 再次批准钥匙串访问。

## 出错时

检查失败不表示“已经是最新版”。请按错误说明处理仓库权限、工具链或网络，然后重试；应用不会自动安装系统依赖。

构建失败保留旧应用。安装前备份失败会停止安装；有任务未完成则稍后再点“安装并重启”。开发窗口、DMG 或没有写权限的安装位置不能自动替换。

安装助手遇到复制、切换或打开失败会尝试恢复旧应用并记录结果；不会自动回滚数据库覆盖新决策。若系统阻止启动，可手动打开保留的旧 `.app`。

开发验证使用临时 Git 仓库、假构建工具、合成数据库、安装目录和浏览器 mock，不读取用户真库。Linux 测试无法代替 Mac 上的 Finder 权限、原生构建与实际替换验收。
